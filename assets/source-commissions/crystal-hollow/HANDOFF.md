# Crystal Hollow environment kit — HANDOFF (Opus commission 2 of 2)

Everything is generated by `../build_crystal_hollow.py` (Blender 4.5.13, deterministic seeds):

```powershell
..\..\tools\blender-4.5.13-windows-x64\blender.exe --background --factory-startup --python-exit-code 2 `
  --python build_crystal_hollow.py -- --out "$PWD\output"      # add --no-render to skip renders (~1 s build)
```

A full build including 10 Eevee renders and GLB re-import inspection takes about 7–11 s on this PC. Nothing outside this commission folder was edited.

## Conventions
The units are metres, with +Y up and each piece's front toward local +Z. The origin is the ground-contact centre, with these exceptions:
- **`cave_ceiling_cluster`**: the origin is the top attachment centre. The geometry hangs down to about −2.8 m.
- **`chasm_arch`**: the origin is at bridge-deck level at the centre of the gap. Its piers go down to y = −5.2 to reach the chasm floor.

`layout.json` placements are relative to the zone centre (52,0,52). `rotation_y_deg` is Godot `rotation.y` in degrees. `facing` makes each prop's +Z point at its control, and makes each wall face the centre.

**Totals:** 49 placements come to **26,439 triangles** (budget 40k), using **9 material slots** (budget 12): CH_RockStrata, CH_RockWorked, CH_CrystalCyan, CH_CrystalOrchid, CH_RuneCore, CH_Timber, CH_Iron, CH_GlowCyan, CH_GlowOrchid. The GLBs are 10 KB to 590 KB each. Every file embeds its own copies of the textures, so Godot will import duplicate images per file. If memory matters, extract the materials once on import (Godot Advanced Import → Materials → "Use External") so all pieces share them.

## Lighting (Godot Mobile / VR)
- Crystals are **opaque** with an embedded base-to-tip gradient texture that is also used as the emissive map. The GLBs carry emission strength 2.2 via `KHR_materials_emissive_strength`, and rune strips use 4.0. They glow without any real-time lights. If crystals blow out in the headset, reduce `emission_energy_multiplier` on import.
- The only transparency is the two glow-pool materials: alpha blend, back-face culled, flat on the floor, no depth-sorting conflicts except with each other. Set `render_priority` below the crystals if you see sorting issues. If blending is expensive on Quest-class hardware, they can simply be removed.
- The renders include the game's existing six `glow_light`s (cyan/orchid at r = 8, y = 2). The kit is designed to need no extra lights. The optional upgrade is one soft cyan OmniLight (range ≈ 6) inside the vault apse at (0, 2.2, −11.6).

## Collision (`layout.json → collision_proxies`)
The meshes contain **no floors and no collision**. The proxies are:
- The vault pillars and apse back wall, plus two shell rocks. These leave the reward area at (0,0,−10.5) and the 2.5 m opening between the pillars fully open.
- The two chasm-arch piers, the waymarker, the lens post and the six spires.
- Walls: keep the existing 16 box walls at radius 14.5 as collision and hide their meshes, or add one box per wall placement: local centre (0, 5.9, −1.2), size 7.4×11.8×2.6. The wall faces sit at radius 14.6, with bottom ledge lips reaching ≈ 14.1.
- No proxies are needed for the ceilings, studs, glow pools or the 3 cm vault floor ring.

## Clearance (automated, in `layout.json`)
Every non-decal placement is checked vertex-by-vertex below 2.2–3 m against these zones:
- the bridge/corridor (|x| < 1.35, z −6.4…−0.8)
- the entry-to-far corridor (|x| < 1.3, z −10…8.5)
- control A and control B (r 0.75)
- the reward (the vault interior only is exempt)
- the return portal (r 1.6)
- both enemies (r 0.9)
- all four ore nodes (r 0.6)

**Result: 0 issues.** The first build flagged the lens post intruding on control B and the golem, so it was moved to (4.2, −6.6), which is 1.9 m from both.
