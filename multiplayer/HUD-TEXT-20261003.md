# Complete HUD text at phone sizes

Functional CSS repair preserves the authored layout and existing controls.
No additional art commission, gameplay change or JavaScript change was needed.

Observed baseline DOM at 390 x 844: the full objective sentence measured 215px,
but a later mobile rule confined it to a 60px nowrap/ellipsis box. The legal
24-character player name had only 97px beside the meters and occupied three
lines. The source strings were complete; JavaScript was not truncating them.

Changes are in `lobby.css`, `styles.css`, `expedition-hud.css` and
`client/field-overlays.css`, under the `Text-fit repair` comments:

- Give the player name its own row above the meters. At 390px the tested full
  name gets 220px and occupies one line; narrower layouts wrap it normally.
- Use the artist's existing short primary-action label in collapsed objectives,
  leaving room for the full next-step sentence. Full action labels appear in
  the expanded drawer and remain available to assistive technology.
- Restore expanded titles hidden by the landscape rules, wrap goals/actions,
  and position the objective below the actual header. On very short enlarged
  layouts the objective wins hit testing over overlapping thumb/weapon controls.
- Remove intrinsic minimum-width overflow from the field guide. Long touch
  captions wrap and the body scrolls vertically inside the original panel.
  Full names remain readable in Party; help details remain available in landscape.
- Override legacy objective clamps at their actual mobile specificity.

## Verification

`tests/browser-hud-text.mjs` uses real input and read-only DOM measurements.
Set the existing `PW_CORE`, `PW_CHROME`, `ACCEPT_BASE` and optionally
`BROWSER_QA_DIR` overrides, then run:

```
node multiplayer/tests/browser-hud-text.mjs
```

For source-CSS review against an existing built preview, `PATCH_HUD_CSS=1`
injects only the four marked repair sections. It does not rebuild or modify
the distribution. Final acceptance used this mode against the root-owned
preview on port 5188; a root-owned build verifies the final bundled cascade.

Final pass: **19.120 seconds**, zero page/console errors. Cases:

- 390 x 844 portrait and 844 x 390 landscape.
- 150% browser-zoom layout equivalents: 260 x 563 and 563 x 260 CSS pixels,
  each in its own mobile context at device scale 1.5.
- Full legal player name, collapsed/expanded idle and active expedition text,
  real Start/expand taps, Party and Field Guide bounds, and scrolling to the
  remaining text. Structured DOM evidence and screenshots are in
  `logs/hud-text/`; selected captures were visually inspected.

This establishes emulated viewport/text/accessibility behavior, not physical
phone acceptance. At enlarged short landscape sizes the objective can cover
part of the equipment strip while open, just as an explicit drawer covers the
game; its full content is scrollable and its controls remain tappable.

## Timing and lessons

Inspection, fixes and final tests: **971.512 seconds**. Timings are also in
`logs/work-timing.csv`. Meaningful failed strategies and corrections:

- The first fixture used a 25-character name; native `maxlength=24` correctly
  shortened input. Use a legal 24-character fixture rather than weakening the
  protocol or treating validation as display clipping.
- CDP-only device metrics were reset by Playwright screenshots to the context's
  original viewport. Those apparent zoom passes were rejected. Use a separate
  context per layout/scale and assert `innerWidth`, `innerHeight` and DPR after
  screenshots. The final four contexts report the expected distinct dimensions.
- At 150% portrait, long unbroken touch captions expanded the grid's intrinsic
  minimum width despite wrapping normal paragraphs. Set `min-width:0`, use
  `minmax(0,1fr)` tracks, and permit the caption/key badges themselves to wrap.
- Real taps found two stacked interception problems in short landscape:
  the joystick first, then the equipment strip. Check both DOM geometry and
  real input; source/CSS inspection alone missed these. Both are corrected
  only for layouts at most 320 CSS pixels high.
