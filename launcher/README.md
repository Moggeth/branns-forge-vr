# Brann's Forge launcher

Double-click `../Brann's Forge Launcher.cmd`, or use the **Brann's Forge** desktop shortcut. The window remains open after it starts a game. On **The Adventure**, choose the player role and whether the Hero uses the VR headset or monitor. Director defaults to the fast native tactical window; the browser view is a slower fallback. Little Wing and experimental fuel can be added to a game. Hover controls for short explanations. **Labs & Demos** contains the animation, visual, weather, Bellworks, and Ember Gallery stages; selecting one explains whether it uses saves or replaces a managed session.

The shortcut starts the launcher without keeping a command window open. Only one launcher window is allowed: opening the shortcut again brings the existing launcher forward. This does not limit the one Godot game, its optional VR mirror, SteamVR/Vive Console, or the managed voice/service helpers. Closing the launcher leaves the game running.

The main start button calls the existing `../start.ps1` with explicit switches; Stop calls `../stop.ps1`. The GUI never constructs a command from free-text input. The old batch entry points are kept under `legacy/` with paths rebased to the project root. The old Visual Lab and Weather Lab desktop shortcuts are backed up under `legacy-shortcuts/`; the one main desktop shortcut now opens this launcher. The exported Ember Gallery remains a historical build rather than automatically receiving current source changes.

For headsets, press **Start Game** even if SteamVR is closed. The Adventure, VR Animation Lab, and VR Ember Gallery paths now start SteamVR from its installed location and wait until its server and compositor have been stable for six seconds before opening Godot. If SteamVR never comes up, the launcher reports the failure; check `logs/steamvr-startup.log` and Vive Console/link-box status. `scripts/Ensure-SteamVR.ps1 -ProbeOnly` checks the SteamVR path without starting it. This process check cannot prove that the Vive Pro 2 display is connected, so a red display-error screen still calls for hardware/SteamVR troubleshooting. Switching game modes requires closing the current game window first; the backend does not silently reuse the wrong mode. **Open logs** shows timestamped `launcher-*.out.log`, `launcher-*.err.log`, game/service logs, and `launcher-ui-errors.log`. Closing the launcher does not stop the game; use **Stop managed session** when you want to end the game, voice helper, and service. Stop can cancel/refund an active commission.

To verify without launching the game, run `powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File launcher/launcher.ps1 -Validate` and repeat with `-SmokeTest`. The latter renders both tabs to `outputs/launcher-preview.png` and `outputs/launcher-preview-labs.png`. `-SmokeLaunchDesktop` exercises the actual native Director desktop start path; it leaves the game running and should only be used when a session is not already open. Stop that test game by its recorded PID, or use the launcher's Stop button if shutting the whole managed session down is intended. No paid commission or voice call is made by these checks.

Launcher status regression (2026-09-27): Windows can report that a launch task has exited while its redirected log files are still locked for a fraction of a second. The status timer now reads with `FileShare.ReadWrite` and retries on a transient sharing failure; an empty log is handled as an empty string. The old behavior displayed “Launcher status update failed” and the old batch file could then pause, leaving a blank “Brann's Forge” command window. Do not use `Stop managed session` to clear that cosmetic state: it also ends the game, voice and service. Close only the launcher window or its identified parent console, then reopen the shortcut.
